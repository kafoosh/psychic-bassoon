# A Little Guy — Architecture & Systems

iOS 26.5 SwiftUI magic-trick app. A spectator's secret (a playing card **or** a word)
is covertly captured, then a stickman they draw in a playful sketchbook canvas "comes to life,"
performs, and **reveals the secret** — pulling a wand, conjuring a box, and lifting a
card/paper out of it. A copy of the final drawing is silently saved to the real Notes
app (via clipboard) as a souvenir.

The whole illusion is that nothing on screen ever looks like a magic app: it's the performer's
own Home Screen (a screenshot), a fake Spotlight, and an ordinary drawing app. The performer's controls are
disguised as ordinary gestures and buttons.

## Build / run / verify

```bash
xcodebuild -project "A Little Guy.xcodeproj" -scheme "A Little Guy" \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -derivedDataPath /tmp/alg-dd build

UDID=32AF9EC5-F2F6-4C06-A238-AB990761C7B7      # iPhone 17 sim
xcrun simctl terminate $UDID com.kenneth.A-Little-Guy   # always terminate before launch
xcrun simctl install   $UDID "/tmp/alg-dd/Build/Products/Debug-iphonesimulator/A Little Guy.app"
xcrun simctl launch    $UDID com.kenneth.A-Little-Guy
xcrun simctl io        $UDID screenshot /tmp/shot.png
xcrun simctl ui        $UDID appearance dark|light       # toggle light/dark
```

- **Bundle id:** `com.kenneth.A-Little-Guy`. **Target:** iOS 26.5. **Swift Observation** (`@Observable`), `@MainActor`.
- The Xcode project uses a **file-system-synchronized group** — new `.swift` files under `A Little Guy/` are auto-included; no `.pbxproj` edits needed.
- **`terminate` before `launch`** or the stale binary foregrounds.
- **`cfprefsd` caches `UserDefaults`** across simulator reinstalls — `uninstall` to truly reset persisted settings/handwriting.

### Verification constraints (important)
- **simctl cannot inject touches, keystrokes, or pencil drawing** (install/launch/screenshot/appearance only). The desktop app's **iOS Simulator tool** (`mcp__Claude_Code_iOS_Simulator__control`) CAN tap, long-press and `touch_path` — use it to drive the walkthrough or draw a crude figure; capture with `xcrun simctl io … screenshot` (the tool's own screenshot can lag a step). `simctl spawn … defaults write` does NOT reach the app's container prefs.
- **computer-use** needs macOS Accessibility/Screen-Recording perms for the Simulator (not granted) — can't drive the UI either.
- Consequence: gestures, typing capture, and anything requiring a *drawn* figure must be **device-tested by the user**. To screenshot-verify animation/rig/reveal logic, build `PKDrawing`s in code. The **`RigHarness`** (`Stickman/RigHarness.swift`, DEBUG-only, kept in-tree but **never auto-runs**) is the rig regression suite, scored as FOUR populations: a **CLEAN baseline** (~1900 figures from swappable head/torso/arm/leg variations, line + outline forms — must hold 99% figures / 100% strokes / 0 tears / 0 explosions / **0 validator demotions**; Oct 2026: 1897/1900), an **ADVERSARIAL set** (400 outlier stressors — belts/tails at the hip, hats/raised fists, open/hourglass torso outlines, mono-tube legs, two-stroke limbs, cross-body arms, thick pens, one-legged figures — failures expected, tracked for progress; Oct 2026: 85%, 0 explosions), a **PROPORTIONS set** (600 figures sweeping torso 1.2–3.6u × legs 2.0–4.6u — crotch anywhere from 25% to 65% of neck→feet, where the baseline is pinned at ~56% — plus the λ body (spine + one leg in ONE stroke, truth `.spineLeg`), two-stroke limbs, scales down to 0.45 and thick pens; Oct 2026: 92%, 0 explosions, **0 leg strokes partly labelled arm** — the gate that matters), and the **hand-built user fixtures** (17 as of Aug 2026, each with ground truth; ALL must pass). The explosion scan runs EVERY routine at realistic chrome insets; metrics: legAsArm, **legSplitArm** (a leg stroke carrying a real run of ARM labels — the "leg top hinged at the hip swings up like an arm" failure, must stay 0 everywhere), arm-mass fraction, both-arms-same-side, validator demotions + FALSE POSITIVES (a demotion that undid truth-correct labels — must stay 0 on clean). Each set's report ends with `ALL FAILING SEEDS` (diff runs by seed, not by percentage) and the first 40 failures of each set are dumped as `clean_fail_/adv_fail_/prop_fail_<seed>.png` + `.txt` (truth, joints, per-stroke histograms, and a **step TRACE** — `RigFitter.trace`, DEBUG-only — of the label histogram after every pass, so a mislabel is pinned to the pass that made it). Run it by temporarily adding `RigHarness.run()` to `A_Little_GuyApp.init()` (DEBUG), launching, and reading back `Documents/righarness.txt` + `rig_*.png` from the app container; remove the call again before committing. **Real failing drawings become fixtures:** launch a DEBUG build with `-rigCaptureEnabled YES` and every armed drawing is saved to `Documents/cap_<n>.drawing` (hook in `comeToLife`); replay with `RigHarness.replayCaptured()` → `cap_<n>_rig.png` + routine frames, then hand-label it into `userFixtures()`. For non-rig draw-dependent logic, use a temporary harness and delete it after.

## State & routing (the spine)

Three reference objects, created in `RootView` and passed down explicitly (no `@EnvironmentObject`):

- **`AppState`** (`App/AppState.swift`) — single source of truth for `launchState` (`.screenshot` / `.spotlight` / `.canvas`) and the committed `reveal: RevealPayload?` (the secret). The secret lives in memory only — **never persisted, logged, or printed.** Holds the partial card capture (`capturedValue`, from a grid or screenshot-icon tap) until a suit bubble commits it (`commitCard(suit:)`).
- **`Router`** (`App/Router.swift`) — intent layer over AppState+Settings; the only place that decides which screen shows and commits the secret (`restingLaunchState`, `openCanvasFromScreenshot`, `transitionToSpotlight`/`cancelSpotlight`, `commitWord`, `goHome`, `applyInputMethod`, `openSettings`). Also owns `showSettings`.
- **`SettingsStore`** (`Settings/SettingsStore.swift`) — `@Observable` + `UserDefaults` in `didSet` (NOT `@AppStorage` — computed `@AppStorage` is invisible to Observation). Typed fallbacks in `init`.

`RootView` (`App/RootView.swift`) also creates `GlyphStore`, `ScreenshotStore` and the zoom's `ScreenshotLaunchModel`, and injects them explicitly. Home Screenshot → `screenshotStack` (screenshot + Spotlight + canvas + zoom overlay); Canvas Grid → `CanvasScreen`. It overlays `SettingsView` (zIndex 50) when `router.showSettings` and the walkthrough (zIndex 100). **`preferredColorScheme` is set at the root** (canvas `.light`; the screenshot picks whichever status-bar text reads on it; Spotlight `.dark`) — it's root-precedent, so a child override is ignored.

## Input methods (Settings ▸ Input ▸ Input Method → `SettingsStore.inputMethod`)

**Canvas Grid (default, `InputMethod.canvasGrid`)** — the app opens STRAIGHT onto the Little Guy canvas (`Router.restingLaunchState == .canvas`; `goHome` returns to the canvas). Always Little Guy chrome (`SettingsStore.effectiveStyle`; `appStyle` is kept hidden for future styles). No keyboard / title text view.
- **Value:** the paper is a faint ruled sketchbook with a 4×4 grid (`Input/Grid/ValueGrid.swift`): rows A–4 / 5–8 / 9,10,J,Q / whole bottom row = King (ruled like the others — no visual tell). A 1-finger TAP or the touch-down point of a 1-finger DRAG (`GridInputCatcher`, real UIKit recognisers, live on frame one) → `appState.captureValue`; last touch before a suit wins; optional faint `.soft` haptic (`gridTapHaptic`). Works while idle, performing, or done — never while drawing (PencilKit sits above the catcher). The grid's top is the MEASURED bottom of `GridToolbar` (`onGeometryChange` → `gridChromeBottom`), which also sets `stageInsets().top` in Grid mode — no hand-tracked constant.
- **Suit:** `GridToolbar` (`Input/Grid/GridToolbar.swift`) replaces back/menu/draw with four "draw" bubbles in CHaSeD order — art in ONE table, `SuitIcon` (paintpalette / eraser / pencil.and.scribble / square.and.pencil; only the rightmost is filled orange). Pressing one → `appState.commitCard(suit:)` (uses + consumes `capturedValue`; **no grid tap first → no secret, and ✓ will NOT arm** — the bubble is then just a draw button) → **auto-fresh** (if the controller isn't idle, clear page + `controller.reset()`) → drawing mode. In drawing mode the row is Undo (left) · Done ✓ (right) — the shared `StickerUndoButton`/`StickerDoneButton` (`Canvas/StickerButtons.swift`), same arm/disarm as before.
- **Ribbon:** "DRAW A LITTLE GUY" centred under the row (hidden — not removed — while drawing, so the measured height doesn't move). LONG-PRESS → menu (Animation ▸, Settings, New Page) via `ToolbarMenuButton(primaryAction: false)` (UIKit's built-in menu long-press).
- **Settings:** ribbon menu, or a 3-finger swipe down on the page (idle only, `GridInputCatcher`).
- **Walkthrough (Playing Card Reveal):** `WalkthroughEngine.begin(.card, method:)` picks `gridScript` / `screenshotScript`; next/back walk the script. Both open with `welcome` (have a card chosen and secretly *peeked*) → `peekChoice` (two buttons: "Teach me how to peek a card" = accent, "I know how" = dull; `choosePeek(teach:)`) → the optional 7-step peek lesson (`peekDribble`…`peekDone`, filtered out of `script` unless `teachPeek`; see `PeekLessonView`). Grid script then: `gridMap` (every cell labelled A…Q + one wide K, drawn by WalkthroughOverlay from the `.valueGrid` anchor) → `gridValue` (`.valueCell` ring) → `gridSuit` → `suitKey` → draw/✓/reveal → `gridMenu` → `gridAgain` → settings (`settingsInput` → `settingsOtherMethod` — "to learn the other method, change the input method and run the walkthrough again", rings Playing Card Reveal — … `settingsWord`, which rings the Word Reveal row) → `done`. Cards are kept short — one idea each.

**Home Screenshot (`InputMethod.homeScreenshot`, raw 2)** — the app rests on the performer's OWN Home Screen screenshot (`LaunchState.screenshot`, `ScreenshotHomeView`) ; everything after the value is Canvas Grid (the canvas, suit bubbles, ribbon menu and no-input gate are shared).
- **Value:** `HomeScreenGeometry` (`Input/Screenshot/`) is the single source of hit math / Settings overlay / zoom origin. **Where the grid comes from, in order:** (1) an **auto-fit found in the performer's screenshot** — `HomeGridDetector` (Vision text recognition; the app-name labels under the icons give the 4 column centres + row lines; an evenly-spaced best-WINDOW progression search drops widget captions/axis labels; icon = fallback icon × fitted/fallback column pitch; icon centre = label centre − icon/2 − 14.5pt; dock comes from the fallback — it has no labels). Run off-main in `ScreenshotStore.fitGrid` on import (and once, lazily, for older imports), persisted as `HomeScreenGeometry.Fit` in `home_screenshot_grid.json` tagged with the SCREENSHOT's own point size (pixels ÷ screen scale), so on an iPhone Duo a folded screenshot fits the folded screen; an empty file = tried and failed. Only applies when the current window size matches. (2) else a table MEASURED from real SpringBoard screenshots — iOS 26 iPhones 390×844 / 402×874 / 440×956 (bottom dock) and iOS 27 **iPhone Duo folded 466×678 / opened 951×669 (landscape; widgets left, grid right of centre) with a SIDE dock** (`Dock.side`: a 4-icon column at the right edge, hit by height); unknown sizes borrow the nearest-SHAPE (aspect) entry, uniformly scaled. (3) the performer's calibration on top, **per screen size** (`SettingsStore.gridCalibration(for:)` / `setGridCalibration`, key "WxH"; the pre-V2 single calibration applies to any size without its own). Taps left of the grid (an opened Duo's widget area) are ignored. Verified in the Duo sim (folded + opened, real SpringBoard pages filled with 24 probe apps) and on iPhone 17: auto-fit within ~1pt of measured. Everything that builds a geometry uses the live window size (`ScreenshotZoom.screenSize` = key window bounds) and re-reads it on resize (GeometryReader), so folding/unfolding swaps layouts live. 28 sections (`slot(at:)`: 24 icon spots row-major + 4 dock spots), each carrying a value from `SettingsStore.screenshotSlotValues` (0 = None → the app still opens, no card, ✓ won't arm). Default (`HomeScreenGeometry.defaultValues`) mirrors the canvas grid: icon row 1 A–4, row 2 5–8, row 3 9–Q, rows 4–6 + dock King. The performer reassigns any section by tapping its box in `ScreenshotSetupView` (a `Menu` + `Picker`). Above row 1 → no section (tap ignored). The placeholder (no screenshot yet) has NO `GridInputCatcher` over it — a UIKit view above SwiftUI wins the hit test and swallowed its "Open Settings" button. Widgets sit on the same row grid, so they don't matter. Taps come through `GridInputCatcher`.
- **Zoom:** `ScreenshotZoom.open` — the canvas MOUNTS immediately (opacity 0 while `.opening`) and a launch image of the fresh canvas (`ImageRenderer` of paper + grid + scatter + `GridToolbar(showsMenu: false)`, grid top from `GridChromeModel.lastBottom`) grows out of the tapped icon in `AppZoomOverlay` (Animatable; uniform content scale, rounded mask morphing icon→screen corner, the icon cropped from the screenshot cross-fading out), while the screenshot pushes back ×1.08 + dims. **The animation is started on the NEXT run-loop turn** — animating `progress` in the same update that inserts the overlay gives SwiftUI no from-frame (it sat at the icon). Close: `ScreenshotZoom.close` snapshots the live window (`drawHierarchy`), sets `.screenshot` (canvas unmounts → fresh page next time) and shrinks the snapshot back into the icon. The overlay exists ONLY while animating (gotcha 8). The full-bleed layers ride in `.overlay` on a safe-area-ignoring `Color.clear` — a fixed screen-size frame directly in the stack inflated it and shoved the canvas under the status bar.
- **Ribbon menu:** in this mode the last row is **Return to Home Screen** (`GridToolbar.onReturnHome`) instead of New Page — an UNCONDITIONAL trick reset (works mid-performance too) that runs the same close zoom after a 0.3s beat so the dismissing menu isn't in the snapshot.
- **Close gesture:** a 1-finger swipe UP starting in the bottom band (home-indicator inset + 90pt; ≥50pt rise or a quick flick; diagonal thumbs up to ~50° off vertical count) — `GridInputCatcher.onSwipeUpFromBottom`, gated by `CanvasScreen.canSwipeHome` to idle-before-suit and finished-reveal (`controller.phase` idle/done; never drawing/armed/performing). `RootView` sets `.defersSystemGestures(on: .bottom)` at the ROOT while the screenshot method's canvas is up, so iOS yields the first swipe to the app (a second swipe still leaves). The original thin 50pt strip + strictly-vertical test was unreliable for real thumbs on device.
- **Screenshot + live clock:** `ScreenshotStore` (JPEG at `Documents/home_screenshot.jpg`, force-decoded; clock metadata in `home_screenshot_clock.json`). **iPhone Duo: an optional SECOND screenshot** — `ScreenshotStore.Slot` `.main` (every iPhone; a Duo's folded/portrait screen) and `.opened` (Duo landscape, files `home_screenshot_opened*`). Each import lands in the slot of its own SHAPE (Duo only — elsewhere always `.main`); `current` = the slot for `store.screen` (kept current by ScreenshotHomeView/ScreenshotSetupView on resize) else whichever exists, so folding swaps screenshots live and neither is required. `ScreenshotSetupView` shows Folded / Opened rows (each Add/Replace + remove, "Optional") only when `isDuo` (= the screen's fallback layout has a side dock); other iPhones keep the single picker. Import prep (`ScreenshotPrep.prepare(_:shotSize:)`) runs the clock eraser in the screenshot's own point size, not the current screen's. On import `ClockEraser` finds and erases ONLY the clock: search region from the top safe inset (notch/Dynamic Island → left ear, x ≤ 42% W, y ≤ inset; home-button 20pt bar → centre 40%); per-row median background; "ink" = near-PURE white (>0.94) or near-black (<0.16) pixels clear of their row background, dominant polarity wins (= text colour, which covers light/dark wallpaper + appearance — a plain contrast threshold missed white-on-pale-sky); columns clustered (≤6pt gaps) → heaviest = the time; sanity 18–120pt × 7–24pt. Erase = Coons-style border interpolation of the 3pt-padded box + 2× box blur. Result `StatusClock` (rect, lightText, fontSize = core digit height / 0.705 — a 17pt clock measures 12.0pt). `LiveClock` (TimelineView `.everyMinute`, locale 12/24h, no AM/PM, SF semibold) draws the current time there, and `RootView` sets `.statusBarHidden` while the screenshot is up (incl. the open zoom) so nothing doubles; the screenshot's own signal/Wi-Fi/battery stay as captured. Verified on iPhone 17 (island, white + inverted dark text), a light-mode capture, and iPhone 13 Pro (notch, white on pale sky). Screenshots imported before this (no clock JSON) or with no detectable clock fall back to the system status bar (`prefersDarkStatusText`). Settings ▸ Input ▸ Home Screenshot → `ScreenshotSetupView` (pick / remove, grid overlay with value labels — **shown before any screenshot too**, on a stand-in screen, so values can be assigned up front; follows the fold; scaled to fit the row on wide screens — two drag handles (screenshot only), Reset to Auto, aspect warning, a footer saying whether the grid was auto-found).
- **Canvas in this mode:** the ruled grid is decoration only — `captureGridValue` is gated to `.canvasGrid`, so no canvas value capture and no tick (the Grid Tap Haptic row is Canvas Grid-only). Zoom springs: open 0.30s, close 0.28s.
- **Word method (pull-down):** a 1-finger swipe DOWN on the screenshot (`GridInputCatcher.onSwipeDown`; the catcher runs with `valueOnDragStart: false` here so only a TAP opens an app) → `router.transitionToSpotlight()` → the fake Spotlight (`Input/Spotlight/SpotlightView`), laid over the screenshot in `RootView.screenshotStack`. Its suggestion tile reports its icon frame and calls `onOpenApp` → `ScreenshotZoom.open(from: tile) { router.commitWord(word) }` (zoom out of the tile). On the canvas any suit bubble just starts drawing — `AppState.commitCard(suit:)` KEEPS a `.word` secret when no value was captured. `cancelSpotlight` returns to `restingLaunchState`.
- **App-open icon:** the zoom surface carries the A Little Guy icon (`LittleGuyIcon` asset) on OPEN — the tapped icon "becomes" the app — and the original icon cropped from the screenshot on CLOSE (`ScreenshotLaunchModel.closeIcon`), so it lands back as what was there.
- **Value crib:** `SettingsStore.screenshotShowValues` + `screenshotValuesOpacity` (default off / 20%) draw each section's value faintly centred on its icon (`ScreenshotHomeView.valueLabels`); set in `ScreenshotSetupView`.
- **Walkthrough:** `screenshotScript` — `shotIntro` (black stand-in screen when no screenshot is set, so the copy says it is GOING to be their Home Screen) → `shotMap` (ghost outline + value on every icon spot, from `HomeScreenGeometry`) → `shotValue` → the shared card beats (`gridSuit`, `suitKey`, draw/✓/reveal) → `gridMenu` → `swipeHome` → settings (incl. `settingsOtherMethod`, `settingsShot`, `settingsWord`). The word method is its OWN walkthrough — **Word Reveal** (`begin(.word, …)`, `wordScript`): `wordWelcome` (word reveals need Home Screenshot) → `wordIntro` on `.screenshot` → `wordType`/`wordCapture`/`wordOpen` on `.spotlight` → `wordDraw`/`wordReveal` on the canvas → `wordDone`. It always runs on the Home Screenshot screens: the engine forces `method = .homeScreenshot` and `RootView.shownMethod` (walkthrough's method while active, else the setting) mounts `screenshotStack` — so it plays under Canvas Grid too, without ever changing the saved Input Method. `SuitKeyPanel` (in WalkthroughOverlay) shows each real bubble → the look-alike it hides: palette ≈ C, eraser outline ≈ H, scribble ≈ S, square tipped 45° ≈ ◆.

**Home Screen (fake home) — REMOVED.** The original coded fake iOS home (swipe-start icon capture, home editor, wallpaper), the Basic/Notes styles and Liquid Glass were removed; `InputMethod` raw value 1 is retired (a stored 1 decodes to nil → Canvas Grid). How it worked is written up in **`docs/legacy/HOME_INPUT.md`**; the code is in git history before the removal.


Souvenir: when the performance finishes, the drawing is silently copied to the clipboard via **`UIPasteboard`** (`CanvasScreen.copySouvenir`) so the performer can paste it into the real Notes app (iOS sandbox forbids silent note creation; manual paste accepted).

### Stickman/  (the rig + animation engine)
- **`RigModel.swift`** — `BodyPart` (torso, head, l/r arm, l/r forearm, l/r leg, l/r shin), `RigStroke` (polyline + per-point part + colour/width + **`rigid`** = closed-loop silhouette: indivisible, never split at the elbow/knee), `Skeleton` (joints incl. elbows/knees + hand anchors), `FigurePose` (per-joint angles), and `Rig.worldPoint(_:part:pose:)` — **two-level hierarchical FK**: bend the lower segment about elbow/knee, swing the whole limb about shoulder/hip, then the root (squash-about-feet → lean-about-hips → translate). Joints a child rotates about are carried by the parent → strokes crossing a joint don't tear.
- **`RigFitter.swift`** — `fit(drawing, traits:)`. **Silhouette-run model** — works for BOTH thin stick figures AND fuller-bodied characters (filled/outlined torso + arms + legs). The key insight: a stickman's strokes ARE its bones, but a fuller body's strokes are **silhouette OUTLINES** of thick parts — the bone is the medial axis of a filled region, not any stroke. So we don't classify the drawn lines directly; we reason about the silhouette. Pipeline: sample→densify (flag each stroke `closed` and `fat`) → **rasterize** to an occupancy grid (`RasterGrid`: a `closed` OR `fat` stroke — any 2D outline, incl. an open "U" — is scanline-FILLED as a solid polygon so an outline reads as one solid run; thin strokes stamped as thick discs; NO morphological close — it would bridge a narrow leg inseam) → read each row's horizontal **runs** → detect head/neck/spine/crotch/torso-width → label every cell by run → **classify fat strokes as whole limbs by position** → **consolidate thin leg strokes + raise the hip** → skin → joints → confidence (`>=0.5` articulates, else graceful all-torso fallback). **Resolves each stroke colour against the canvas `traits`** so a white-in-dark figure stays white. **Standing-figure priors** are exploited throughout (head on top, legs down, arms to the sides).

  **Single-tap DOTS survive (the anti-"vanishing eyes" fix).** A dotted eye/nose samples as ONE control point (or a tap cluster with no extent), so it died on the old `pts.count >= 2` guard in Step 0 — face details vanished the moment the figure came to life. Any stroke with sub-pixel extent is now normalized to a ~0.7pt sliver instead of dropped: its bbox becomes real (the head detail-folding pass then binds it to `.head` so it rides the head), and the stage's round line cap paints it as a dot of the pen's width (a zero-length path can render as nothing). Verified by the harness's **`dumpDotFaceCheck()`** (writes `dotface.txt`): 1-point, zero-extent-cluster, and sub-pixel dot strokes all survive, bind to the head, and track it through the full Classic routine.

  **`spineX` (the centreline) is tracked with a per-row CAP.** Each row's centreline moves toward the nearest run's centre by at most `~½ cell` — the spine is near-vertical, so a big jump means an arm merged into the spine run, and an uncapped tracker would drift ONTO the arm (mislabelling that arm as torso and the spine as an arm — the asymmetric "one arm dies" bug). Capping keeps it on the spine yet still follows a gradual lean.

  **Fat (outline) limbs that TOUCH the torso are classified WHOLE, by position** (the merged-silhouette fix). When outline arms/legs touch the torso they fuse into one blob, so per-row runs can't separate them and there are no torso-only rows to measure a waist from. So each fat (non-head) stroke is labelled as a unit by where its centroid sits relative to the **lean-tracking `spineX` at its own height**: a stroke near the centreline is TRUNK → torso (this covers both the torso AND a drawn NECK — both sit on the spine, so an outlined neck rides with the torso instead of being mistaken for an arm); a laterally-offset upper stroke is an arm; a lower stroke is a leg (by side). The tight threshold (`~0.6·torsoHalfW`) keeps an arm hanging beside a wide torso lateral; comparing to `spineX` (not the head x) keeps a leaned torso central. Thin strokes keep the silhouette per-point labels (stick figures untouched).

  **Leg consolidation + hip-raise (the anti-"leg-top-as-arm" fix).** The gap-based crotch sits too LOW when legs meet at a point (inverted-V) or thick strokes overlap near the join, so the leg TOPS get mislabelled as arms — which drags the elbow/hand down the body and **flings the limb when it animates** (a wave rotates it ~115°). A one-sided leg-dominated stroke is made one whole leg; the hip then **rises to the topmost leg point** so the leg pivots where it really attaches. Each **shoulder snaps to the arm's actual root** (nearest arm point to the neck) for the same reason.

  **Arms drawn OFFSET down the torso — Step 7c arm-stroke consolidation (the anti-"stretched body" fix).** An arm attached BELOW the shoulders — or one whose first segment dips across the spine before heading out (a Z-arm) — keeps TORSO labels for its near-centreline points, so ONE pen stroke ends up split torso|arm: when the arm swings, the torso-labelled points stay with the body and the segment between the two groups visibly STRETCHES the figure (and the shoulder snap can land mid-stroke). Step 7c mirrors the leg consolidation: a thin stroke that is arm-DOMINATED — or an upper-body stroke (root above `neckY+0.40·bodyLen`, ≥80% arm+torso) with **≥ max(5, 20%) arm-labelled points** (the exit evidence: the trim line already sits 25% beyond the measured torso wall, so a RUN of points past it is a limb; a distance margin on top double-counts and misses arms on wide bodies) — becomes ONE whole arm on its dominant side, and the Step-8 shoulder snap then finds its true root, so an offset arm pivots where it was actually drawn to attach. A stroke with balanced arm mass AND far lateral reach on BOTH sides (both arms drawn as one chest-wide line) keeps its per-point split. Verified: `ArmVariant.lowAttach` across the whole suite (386 figures, 50%→2% failure) + the `offsetArm` user fixture (photo-replica with a Z-arm) — arms whole, no stretch, 0 arm→torso beyond noise, explosions still 0.

  **Legs drawn TO THE SIDE — Step 5b leg-stroke-first detection (the anti-"side-leg" fix).** The run-gap crotch (Step 4) assumes legs descend roughly straight and splay EVENLY about the spine. It breaks two ways: (A) both legs **veer to ONE side** with their tops close together → the crotch lands too low and the lateral leg points read as ARMS (the legs then swing about the shoulders and FLING — arms wrap the head, a leg shoots off-screen); (B) **crossed/scissor legs** → a single leg gets split across the crotch and the two halves rotate oppositely in the scissor walk, tearing the leg. Fix: a dedicated **Step 5b** finds the THIN lower-body LEG strokes directly by their **ROOT** (top/min-y end), sides each WHOLE stroke by **relative root order** (not side of any axis — so two legs both veering one way still resolve to one left + one right), and relocates the single central hip to the roots' **median convergence** (never the foot position). The arm/leg boundary is a **root-HEIGHT gate** (legs root below `neckY+0.40·bodyLen`; arms root at the shoulders, far above) — provably side-agnostic, so every arm stays an arm (harness confusion matrix shows **zero** arm→leg). Detected legs are then **whole + indivisible** (override the per-point labels; skip the Step-7b inverted-V split and the feet-biased hip-raise), so a side/crossed leg can neither be mislabelled nor tear. Gated on ≥2 detected leg strokes, so one-legged/degenerate figures stay on the proven path.

  **BOTH limbs drawn in ONE ∧/∩ stroke — the limb-pair split (the anti-"single-stroke arms vanish" fix).** Arms drawn as one arch (left hand → up over the spine → down to the right hand) or both legs as one inverted-V have real 2D spread, so the PCA `fat` test read them as an OUTLINE: the stroke was polygon-filled, bound rigid, and Step 7a classified it WHOLE — the arch's centroid sits ON the spine, so both arms became TORSO (and an ∧ legs stroke one whole leg glued to one hip). Two complementary fixes. (1) **`isFat` requires a DOUBLE-BACK along the major axis**: an outline's two walls run the shape's length out AND back (travel ≈ 2× the extent, like a loop); a bent single line crosses its extent once — so a wider-than-tall arch stays a thin line, gets per-point silhouette labels, and 7c's both-arms test keeps the split. (2) A STEEPER-than-wide arch — and the legs ∧ — genuinely double back along their vertical major axis, so **Step 7a runs `limbPairJunction`**: an OPEN fat stroke whose two ENDPOINTS are free tips on OPPOSITE sides of the body centreline, each well clear of it, is a limb PAIR — NO symmetry assumed. The JUNCTION (where the pair attaches) is the path point nearest the lean-tracking `spineX` at its own height — robust to an off-centre apex and to the noisy pre-consolidation crotch x (the ∧'s own polygon-fill corrupts the run gaps near the feet and inflates the measured waist, hence the modest half-torso clearance) — and each BRANCH is labelled whole by path order (a branch that hooks back across the centreline stays one limb), non-rigid, `pairHandled` so 7b/7c can't re-split it. A genuine outline tube fails the endpoint test — its ends sit TOGETHER at its root — and a torso outline's ends hug the centreline. Verified: fixtures `archArms` (wide ∩, thin path) / `steepArchArms` (tall ∩, 7a pair split) / `archArmsVLegs` (arms ∧ + legs ∧, hip raised to the apex), full suite unchanged (99% / 100% / 0 tears / 0 explosions).

  **Asymmetric arm pairs — different heights, off-centre junction, raised hands, floating roots (the anti-"one arm dies / doubled-arm streak" fixes).** Real drawings violate every symmetry the pair logic could lean on (arms as a check-mark ✓, one arm raised + one hanging, the stroke crossing the spine mid-torso, arms drawn slightly off the body). Four coordinated rules make "whatever hangs off EACH SIDE of the body is that side's arm" the actual behaviour: (1) **7c's both-arms gate is REACH-based, not balance-based** — genuine lateral reach past the torso band on EACH side keeps the per-side split however UNEQUAL the two branches are (the old minority-≥20% balance test collapsed an asymmetric pair onto the dominant side: one arm died, and the dead branch streaked when the live one swung; a single arm dipping across the spine still consolidates — its far-side excursion fails the REACH test). (2) **Shoulders snap to the arm point nearest the TRUNK (`distToSegment` to neck→hip), not nearest the neck** — a hand RAISED toward head height is closer to the neck than the drawn attachment, and a near-flat arm is closest mid-branch; either way the old snap put the pivot on the free tip/middle and the wave rotated the arm about its own hand (the "doubled arm"). Nearest-the-trunk finds the crossing/junction at ANY height. (3) **Step 7d heals the trunk**: an arm crossing the spine drags the tracked centreline for a few rows, so a short run of true spine points fell outside the shifted torso band and RODE THE ARM (a mid-spine chunk tore out on every wave) — on a torso-majority stroke, short interior islands of limb labels bounded by torso (≤ count/6) and 1–2-point end tails are relabelled torso; a genuine spine+arm single stroke keeps its arm (a long END segment, not an island). (4) **`reclaimRaisedTips`**: rows above the neck are labelled HEAD by the silhouette, so a raised hand's tip glued itself to the head and stayed behind when the arm waved — a head-labelled run at a stroke END, adjacent to ARM labels, whose tip is clearly outside the head disc (>1.15·headRadius) is reclaimed by that arm; decorations are untouched (majority-head, no adjacent arm labels, or detail-folded whole — a cell-level variant of this rule broke ears/hair across the suite and was reverted). Verified: fixtures `asymArms` (raised L + low R crossing the spine) / `checkArms` (low hand → high junction → horizontal arm) / `vArmsUp` (shallow V through the spine — the TopHat doubled-arm screenshot) / `floatSideArms` (both arms rooted off the body), wave frames clean, suite still 99% / 100% / 0 / 0.

  **Hip-band ink stays with the BODY (the anti-"hip extends out as an arm" fixes).** The reported outlier family — a belt/tail/leg-top near the hip labelled ARM, then swung ~2 rad about a distant pivot — had four independent entry points, each now closed: (1) Step 6 labels a separate side run DEEPER than 0.55·bodyLen as LEG by side of the crotch (a too-low crotch stranded leg ink in the between-neck-and-crotch band where every side run used to be an arm); (2) the legacy **hip-raise RELABELS the stale band it exposes** — cell labels were assigned against the ORIGINAL crotch, so when the hip moves up, a lower-body thin stroke carrying arm labels re-sides whole as a leg and stale arm-labelled END runs below the raised crotch become leg; (3) 7d's consolidation root gate is **hip-relative** (`min(0.40·bodyLen, crotchY − 0.05·bodyLen)` — bodyLen is measured to the FEET, so on a leggy figure 0.40·bodyLen alone sat AT the hip) with a ≥3-arm-point floor; (4) the **shoulder snap is bounded to the upper trunk** (≤0.65·trunk — the unbounded trunk-wide argmin let a genuine hand-on-hip arm put its pivot ON its own hand at hip height). The crotch itself is more robust: the gap-walk tolerates ~`inkWidth/cellSize` merged rows (a thick pen fills the crotch solid), and the hip-raise uses the ~6th-percentile top leg point, not the single min. The **pair-junction split carries a position veto**: a genuine limb pair folds at the TOP of its stroke (crotch apex / shoulder fold), while an open tube's spine-crossing (its rounded far tip) and an open ∪ torso outline's (its hip bottom) sit at the BOTTOM — a junction in the lower 55% is refused, so a chunky centred leg tube or an open body outline can no longer split into counter-rotating halves (the "body splits open" report). Trunk healing (7c) runs BEFORE arm consolidation (7d) — it could never heal a stroke consolidation had already made 100% arm — with the island bound aligned to the consolidation floor (both n/5; the old n/6..n/5 dead band stayed split and tore mid-spine).

  **Body PROPORTIONS are not assumed — a leg is what reaches the ground (the anti-"leg top swings up as an arm" fix, Oct 2026).** Device testing produced rigs where a chunk of leg, hinged at the hip, swung up like an arm (indecent-looking). Root cause: every lower-body gate was an absolute fraction of body length tuned to the baseline's proportions (crotch ≈ 56% of neck→feet); a SHORT torso with LONG legs roots its legs at 25–40%, Step 5b's leg-first pass went silent, and the Step-4 gap-walk crotch landed mid-leg (thick pen / narrow or crossed legs) — or walked straight UP through hanging arms into the shoulder band (arms touching the leg tops leave no single-run torso rows) — leaving leg tops in the arm band. Fixes, in pipeline order: (1) **Step 4** stops the gap-walk when a row holds ≥3 runs or the gap midpoint jumps (the arm band), but only above the bottom 30% (feet dashes/blobs add runs too). (2) **Step 5b** calls a thin descending stroke a leg if it roots in the lower body AND is leg-long (≥0.25·bodyLen — a two-stroke arm's forearm roots low on a short torso but is short) OR **reaches the ground** (bottom 20%); thigh strokes are **chained** onto a detected shin whose root their foot touches; a **single** detected leg (λ body, one-legged) is still whole + sided by its direction and its root caps the hip from above; the hip floor is 0.20·bodyLen. (3) **Step 7b** never consolidates a leg-majority stroke rooted at the neck (the λ spine). (4) **Step 7e — a thin stroke is NEVER half arm / half leg**: a mixed stroke is a whole LEG if it reaches the ground, roots in the lower body, or is a λ (its arm run sandwiched between a torso run spanning ≥0.6·trunk and a leg run); otherwise a whole ARM; a torso|leg stroke that ends in mid-air rides the root. Runs BEFORE 7d (a folded arm's few leg labels used to fail 7d's arm-vs-leg guard). (5) **Step 7h** chains a dangling leg-labelled segment that does not reach the ground onto the ARM whose end its root sits on (two-stroke arm forearms). (6) **Step 7f** — a small closed blob at a thin stroke's END rides that end's limb (hands hanging below body-mid on a short torso were "lower fat strokes" → legs; a raised fist folded into the head still rides its arm when outside the head disc). (7) **Step 7g** — a thin head-majority stroke that attaches below the neck near the trunk and reaches out beside the head is a RAISED ARM, not head; `foldHead` now also requires nothing below the neck. (8) `detectHead` excludes a candidate with ≥2 GROUNDED strokes rooted along its bottom edge (a short wide outlined body under a small head out-sizes it; a hat on a head has nothing grounded rooting under it) and returns the head's stroke index. (9) Validator: `armRootDepthMax` 0.75→0.92 (an arm attached low inside a short outlined torso first reads ARM where it exits the outline), `leverTrunkMax` 2.2→3.2 (any normal arm is long relative to a short trunk; the extent-relative lever is the real fling test). Harness: `FigureSpec.torsoLen/legLen/lambdaLeg`, `ArmVariant.twoStroke/.crossBody`, `LegVariant.twoStroke`, `TruthLabel.spineLeg`, `lowAttach` root capped at 45% of the trunk. Remaining known misses are graceful (an arm drawn starting INSIDE a wide torso outline rides the torso; a cross-body folded arm rides the torso; a few raised-fist arms on wide heads stay head).

  **Hands are ESTIMATED when a side has no arm-labelled points (the anti-"prop at the shoulder" fix).** A one-stroke outline body (the whole figure in a single closed loop) classifies whole as torso, the low-confidence fallback relabels everything torso, and Auto-Rig-off collapses parts — in all three there are no arm points, so `refineJoints` left the hand anchors AT the shoulders and every conjured prop (wand/rod/brush/hat/card) appeared at the top of the arm. Now, per side with no arm points, the hand = the drawn point most laterally past the torso edge (`>1.25·` the shoulder offset, vs the lean-tracking neck→hip centreline) inside the ARM BAND (below the neck, to a little past the hip — legs are only lateral near the feet, far below), and the elbow = its midpoint to the shoulder. **An estimated hand rides the ROOT, not the invisible arm's FK:** `Rig.leftHandPart`/`rightHandPart` (the prop anchor's CARRYING part) are `.leftForearm`/`.rightForearm` only when some final stroke point actually articulates as that arm; otherwise `.torso` — a routine's arm angles would swing an arm-tip anchor on a long lever far away from the STATIC drawn arm (the "fishing rod far from the arm / out of frame" bug). Every routine anchors its apparatus via **`worldHand(rig, left:, pose, off)`** (`RoutineSupport`), never a hardcoded forearm part. Verified by the harness's **`dumpPropAnchorCheck()`** (`proptest.txt` + end-to-end `prop_*.png` frames rendered through `LittleGuyStage.drawFrame`): on a user-like one-loop outline figure the estimated hands land on the drawn arm tips (0/7pt miss), carrying parts resolve to `.torso` (stick figure: forearms), the Fishing rod stays ON the drawn extended arm through cast/reel/present, and the Classic card presents at the extended hand.

  **Head** (`detectHead`) = the **largest roundish stroke in the top band, nearest the top-centre** (score = `size − 0.6·topOffset − 1.0·centreOffset`). This beats: small ears/horns/eyes/hair (too small), a fat OUTLINED arm in the top band (too far off-centre), and the torso (too low / excluded by the tight top band + aspect gate). The **neck sits at the head's BOTTOM edge** (`maxY`), not `headCenter+radius` — a wide oval head's radius (=width/2) would otherwise reach below it and swallow the shoulders/arm-tops into the head zone.

  **The torso width is MEASURED, not assumed (the anti-"edge-as-arm" fix).** The torso slice at each row is the **central run** (straddling the spine x). Its half-width is taken as the **30th-percentile** of central-run half-widths over the whole torso — the un-merged "waist", since an arm only ADDS width, so a merged arm can't inflate it. The central run is then **trimmed** to `spine ± 1.25·torsoHalfW`: anything inside is torso; lateral overhang (or any separate side run) is an arm by side. A wide rectangle/blob/oval torso is one wide central run → its vertical edges are torso, never arms; arms drawn touching the torso (Character 1's corner arms, Character 2's attached loops) are peeled off by the trim. A thin spine yields a narrow central run, so a stick figure's arms still read as arms (no regression).

  **Outlined limbs rotate as ONE rigid piece (the anti-tear fix).** A `closed`-loop OR `fat` (2D outline, incl. open) stroke is bound to a **single body part** and `splitSegment` refuses to split it at the elbow — so both silhouette walls share one FK pivot and swing as a solid sheet (no shoulder/elbow "scribble"). `fat` is a PCA test (minor/major spread > 0.22) so an open "U" outline is caught too. Thin (line) strokes keep per-point labels and still split arm→forearm for the wave. **Legs are never split** thigh/shin → stiff straight scissor legs. *(Verified with the retained `RigHarness` regression suite — now ~1900 composed figures across head/torso/arm/leg variants in line AND outline forms + decorations/lean/wobble/scale: **100% per-stroke accuracy, 0 tears, 0 edge-as-arm, 0 animation explosions**; baseline old fitter was 78% / 15% tears / 28% edge-as-arm. The harness now also runs the REAL routine and flags any figure whose ANIMATED bbox explodes — label-accuracy alone missed on-device failures (open outlines, inverted-V legs, arm/spine merge) that this caught. Visually confirmed: Character 1 & 2 + a stick + closed/open fuller bodies all rig + animate cleanly through the routine.)* The suite now also covers **legs drawn to the side**: `LegVariant` adds `.sideways`/`.crossed`/`.steepSplay`/`.sideOutline`, plus hand-built fixtures `sideLegX` (scissor-crossed) / `sideLegLean` (both veer one way) reproduced from the user's screenshots — and **arms drawn offset**: `ArmVariant.lowAttach` + the `offsetArm` fixture (Z-arm across the spine). After the Step-5b fix: **99% figures fully correct, 100% per-stroke accuracy, 0 explosions, 0 arm→leg in the confusion matrix** (`leg:crossed` was 100%-failing before). A **`dumpStagingCheck()`** (writes `staging.txt` + `stage_small_*.png`) verifies issue-2: across {small-high, normal, big} figures × all 5 routines with representative chrome insets, the figure (post-drop) and the reveal card stay BETWEEN the header and bottom-bar bands.
- **`RigPlausibility.swift`** — the **post-fit safety net**. The confidence score is presence-based, so a catastrophic mislabel (hip cluster as an arm, whole body as an arm) could still articulate and FLING. This pass runs inside `fit` (after `refineJoints`, BEFORE the forearm split — labels are whole-arm/leg there, and the downstream `leftHandPart`/`rightHandPart` computation automatically resolves a demoted side to `.torso` so props ride the root) and **freezes any geometrically implausible limb to `.torso`** — the graceful per-stroke ride-the-root path — then `fit` re-refines the skeleton against the final labels. Checks (each with wide margin over the worst legitimate harness geometry): **arm-root-depth** (an "arm" whose TOPMOST point sits below 0.75·trunk is a mislabelled hip/waist cluster — the workhorse), shoulder-band, arm-below-hip, per-side ink cap (45%), **fling-lever** (max shoulder→point distance vs figure extent — the analytic form of the harness's animated-bbox explosion test), arm-vs-trunk, both-arms-same-side (freeze the side whose label contradicts the side it occupies), leg-in-chest, and **leg-not-grounded** (a leg-majority stroke that neither reaches toward the ground nor descends is a tail/skirt curl — legs go DOWN). A hip-sanity tripwire or >50% demoted mass escalates to the full non-articulated fallback. Demotions are recorded on `Rig.demotions`; the harness counts them and flags **false positives** (a demotion that undid truth-correct limb labels) — the clean-set gate is 0 demotions. **Tuning stance: if a healthy figure trips a check, WIDEN that one threshold — never add compensating logic.**
- **`AnimationRoutine.swift`** — the **`AnimationRoutine` protocol** (`totalDuration`, `pose(at:) → FigurePose`, `drawProps(_:at:pose:…)`), the **`AnimationSlot`** enum (`.classic/.topHat/.fishing/.painter/.balloon` + `.random`, persisted as `SettingsStore.animationSlot`; `.random` is a meta-slot that `resolved()` re-rolls into a fresh concrete routine on every reveal — declared LAST so raw values 0–4 stay stable), the **`RoutineSetup`** value (rig/dropDistance/walkDX/sideSign/propScale/screenSize **+ `topInset`/`bottomInset`** — the playfield chrome insets, built by `comeToLife` via `stageInsets()`), `FigurePose.rest(_:)` (straightened-leg base), and **`AnimationFactory.make(slot, setup)`**. **`RoutineSetup.make` is chrome-aware:** the floor sits just above the bottom toolbar (`viewport − bottomInset`, not a hardcoded 96), and **`propScale` is capped by BOTH the open-side room (≤0.90·) AND the headroom up to the header (the card rises ≤1.15·propScale)** — with NO inflated minimum, so a small figure no longer forces over-sized props that poke into the header. Each routine threads the insets into `fitOnScreen` (card clamp), the Balloon float height, and the Top Hat fall start so nothing plays behind the chrome.
- **`RoutineSupport.swift`** — easing (`smooth`/`easeIn`/`easeOut`/`lerp`/`phase`), `worldJoint(...)` (project a drawing point to screen at a pose), `DropLand` (fall→squash→settle), and **`Approach`** — the shared opening EVERY routine plays: drop in → wave → **walk to the roomier side** (ends at `Approach.done ≈ 4.7s`). Each routine then performs its trick toward the OPPOSITE (open) side. `comeToLife` sets `walkDX` to the roomier side and `sideSign` to the open side.
- **`SketchInk.swift`** — shared hand-drawn primitives in the figure's ink (`det` deterministic wobble, `sketch`/`sketchPartial` (draw-on), `rectPts`/`ovalPts`, `star`, `sparkles`, `wand`, **`cardFace`** = masked paper + the secret; its **`wipe` param (default 1)** reveals paper+secret top-down while the border always draws whole — the Painter's fill-in uses it so the card has ONE outline, not the old separate-outline + inset-cardFace pair that showed a duplicate border). Every routine draws props through these.
- **`Routines/*.swift`** — the five choreographies, each conforming to `AnimationRoutine`, all opening with the shared `Approach` (drop → wave → walk to the roomier side) then performing toward the OPEN side, drawing props via `SketchInk`/`cardFace`. ~12s each (deliberately unhurried): **Classic** (wand → box floats in from the open side → opens → card rises → **flips** to reveal), **TopHat** (a hat falls from the sky onto the head → lift off to the open side, **tumbling 180° so it ends upside-down in the hand, opening up** — `drawHat` renders the WIREFRAME hat in local space under a `flip`·π rotation about the hat's centre; the flipped opening sits exactly where the upright crown-top was, so the tuned reach/rummage poses, sparkles, and card path all hold → reach the other hand in → rummage → the card rises **OUT OF the hole**: it's clipped to *(the region above the opening plane ∪ the opening ellipse's interior)* and the opening's rim is stroked in two arcs — the FAR arc behind the card, the NEAR arc over it — so the card reads as inside the mouth, not behind the hat, while the hat itself stays transparent; the card also **grows 0.72×→1×** as it rises so it always fits through the drawn opening; no box), **Fishing** (take out a rod with the line dangling → **cast the line out to the open SIDE** → bite → reel struggle → **pull the card in from the side** on the hook), **Painter** (raise the wand → **wave it** → a glowing beam **extends out** from the wand tip to where the card will appear → the wand then traces the outline with a progressive **draw-on**, the beam projecting from the wand to the moving tip → face wipes in → lifts), **Balloon** (inflate a balloon **beside his face** toward the open side → float up → pop → card settles). - **`LittleGuyStage.swift`** — transparent overlay aligned to the canvas (`.ignoresSafeArea(.container, edges: .bottom)` + subtract `originOffset`/contentOffset). `TimelineView(.animation)` + `Canvas` redraws the rigged strokes each frame, then draws the reveal props. Holds the final frame; `onFinished` fires once.
- **`LittleGuyStage.swift`** — the transparent performance overlay. Computes the pose once per frame and renders the figure + `routine.drawProps(...)`. ### Reveal/
- **`RevealContent.swift`** — draws the secret onto the card **in the figure's ink colour** (`ink:` param): a **playing-card face** (corner value+suit, big centre pip) or a **word**; **typed** (system font) or **handwriting** (glyph strokes, per-char font fallback). Value, suit, and centre pip all go through `drawGlyphText` (handwriting-first: captured glyph if present, else loose text) — so **captured suit symbols (♣♥♦♠) render in the performer's own hand** too, with graceful fallback per token. Typed text is rendered **per-glyph via `drawLooseText`** with deterministic position/rotation wobble (`det()`, index-keyed → no shimmer) so it reads hand-lettered. The card's **bottom-right index is rotated 180°** like a real playing card (`drawIndex(upsideDown:)` rotates the value+suit group about the corner). Uses `GraphicsContext.resolve(Text).shading`.

### Handwriting/

## Critical gotchas (hard-won)

1. **`@State` writes from escaping UIKit callbacks don't re-render a freshly-mounted SwiftUI view; `@Observable` reference-object writes do.** This was the root cause of the old fake home's cold-start dead-swipe bug. Any state mutated from a `UIViewRepresentable` coordinator / gesture closure must live on an `@Observable` object (e.g. `GridChromeModel`, `Router`, `LittleGuyController`), not local `@State`.
2. **`preferredColorScheme` is root-precedent** — the root-most non-nil value wins; child overrides are ignored. Set appearance decisions in `RootView`.
3. **PencilKit colours invert with appearance** — resolve `stroke.ink.color.resolvedColor(with: traits)` to a concrete RGBA before rendering elsewhere (the `Canvas`/stage), or a white dark-mode stroke turns black/invisible.
4. **The performance overlay must sit *below* the toolbar in the ZStack**, and be transparent + aligned to the canvas — otherwise it swallows the note chrome and the figure "jumps" on appearance. **Consequence:** anything the animation draws in the top header band or the bottom toolbar band is OCCLUDED by the chrome ("blocked by header/bottom row toolbar", worst for a small figure with over-sized props). So the routines must keep the figure + reveal inside the **playfield** = canvas minus the real header/footer insets — see `RoutineSetup.make` (chrome-aware floor + playfield-capped `propScale`) and the per-routine `fitOnScreen`/Balloon-float/Top-Hat-fall insets.
5. **simctl alone can't draw/type/swipe; computer-use lacks perms.** The desktop app's iOS Simulator tool *can* tap, long-press and `touch_path` — enough to drive the walkthrough and draw a crude figure — but multi-finger gestures and real handwriting still need a device. Use the synthetic-drawing harness for rig/animation logic.
6. **Stop animation timelines when idle.** `TimelineView(.animation)` ticks at the display refresh rate *continuously*. `LittleGuyStage` switches to a single static `Canvas` once the choreography `finished` (instead of holding the final pose under a live timeline) — otherwise it re-runs full FK + reveal text-resolution forever and the whole app feels laggy. Any always-on timeline must idle out.
7. **Gate offscreen-forcing effects; don't leave them in the chain at "zero".** A `.blur(radius:)` / `.shadow` / non-rect mask / group `.opacity(<1)` with a *dynamic* value forces a full-screen OFFSCREEN render pass EVERY frame the view re-evaluates — even when the value is 0 (SwiftUI can't prove it's a no-op). Wrap such effects in a `ViewModifier` that applies them ONLY while active , so the idle path has no effect modifier at all. Pre-bake static blurs to a bitmap instead of a live `.blur()`. `.clipped()` (rectangular) is cheap — it maps to `masksToBounds`, no offscreen.
8. **Conditional insertions straight into `CanvasScreen`'s top-level `ZStack` were silently dropped.** The body re-evaluated with the condition true, but the inserted child never mounted (no `onAppear`): the reveal stage never appeared (the drawing hid, nothing performed) and the walkthrough's conditional anchors never reached RootView. Wrapping the conditional in an ALWAYS-PRESENT container (`ZStack { if … }`) fixed the stage; the anchors are now emitted unconditionally. Keep new conditional content inside a stable container there.
9. **Toolbar sizing must not scale with width past phone size.** Sticker bubbles were `screenWidth/8.5` → ~88pt on an opened iPhone Duo (~750pt wide). `StickerMetrics.buttonSize(screenWidth:scale:)` clamps the reference width to `maxReferenceWidth` (430) — the ONE formula (CanvasScreen's header fallback + the walkthrough's suit/✓ hints call it too). The suit row is capped to that width and centred; the value grid already starts at the measured toolbar bottom, so it simply grows to take the room.
10. **Never hand-measure a new phone for the Home Screenshot map first — let the screenshot fit it.** The table is only the no-screenshot fallback. To measure a sim for the table anyway: install ~24 renamed copies of the app (`CFBundleIdentifier`/`CFBundleDisplayName` + `codesign -f -s -`), `simctl shutdown`, rewrite `data/Library/SpringBoard/IconState.plist` so page 1 holds 24 of them and `buttonBar` 4 (delete `DesiredIconState.plist`), boot, `simctl io screenshot --display=<id>` (the Duo has two displays: 1 = folded, 3 = opened; folding needs the desktop app's simulator panel), and run the detector on it. Back up / restore IconState and uninstall the copies after.
